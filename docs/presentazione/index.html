Le regole sui dati

  • Valori derivati calcolati con formule, mai incollati
  • Ogni dato ha una fonte tracciabile
  • Le incoerenze non vengono corrette in silenzio: si segnalano ⚠️

Esempio: alcuni comparti "garantiti" risultano al 100% azioni. Quasi certamente il dato è invertito nella fonte: resta così, segnalato, finché non viene verificato sulla Scheda costi.

Per chi mantiene il progetto

✏️ Excel→ ⚙️ export JSON→ 👀 anteprima locale→ 🔀 PR su master→ 🚀 deploy + release

↓ i passi uno per uno

1. Dati e anteprima

python scripts/export_xlsx.py   # Excel → JSON, con validazione
./scripts/anteprima.sh          # export + test + http://localhost:8000

Il file Excel si modifica in Excel, così i valori delle formule restano in cache.

2. Pull request e release

  • La CI sulla PR verifica dati, test e sito, e annuncia la versione
  • Al merge: deploy della GitHub Page, poi tag vX.Y.Z e release con note e allegati (dati JSON, Excel, zip del sito)
  • minor per sito:/script:/feat:, patch per il resto
  • major solo su decisione esplicita del responsabile

3. Documentazione sempre allineata

python scripts/screenshots.py   # rigenera gli screenshot

Ogni modifica alla dashboard aggiorna insieme guida, presentazione, screenshot e CLAUDE.md.
